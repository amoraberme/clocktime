## 1. Why adding employees fails

Adding a person works in a clean environment; the end-to-end test signs up an owner and adds a team member. It fails in production for these reasons, from most to least likely.

### 1.1 The invite email fails (bug, fixed)

|                         |                                                                                                                                                                                                                                                                                                                                                                                     |
| ----------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Where**               | `src/server/services/team.ts`: `addEmployee` and `sendInvitation`                                                                                                                                                                                                                                                                                                                   |
| **What you see**        | "Something went wrong. Please try again." Trying again then says "\<email\> is already on your team."                                                                                                                                                                                                                                                                               |
| **Why**                 | The person is saved first, then the invite email is sent. If the email service refuses it, the whole action reports failure, even though the person was already saved. A new Resend account refuses mail until the sending domain is verified: before that it only delivers to your own address. A wrong `RESEND_API_KEY` or an `EMAIL_FROM` on an unverified domain does the same. |
| **Fix**                 | The add now succeeds and shows a warning, e.g. "The invite email to ana@… couldn't be sent (the email service refused the sender or the API key). Check the email settings…, then use Resend invite." **Resend invite** on the person's profile gives the same clear reason. CSV imports benefit too, because the same function runs for each row.                                  |
| **What you need to do** | In Resend, verify your domain (SPF and DKIM records). Set `EMAIL_FROM` to an address on that domain, e.g. `ClockTime <no-reply@yourdomain.ph>`. Check that `EMAIL_PROVIDER=resend` and `RESEND_API_KEY` are set in Vercel for **Production**.                                                                                                                                       |

### 1.2 Duplicate employee number (bug, fixed)

|                  |                                                                                                                                                         |
| ---------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Where**        | `addEmployee` and `updateEmployee`                                                                                                                      |
| **What you see** | "Something went wrong. Please try again."                                                                                                               |
| **Why**          | An employee number typed by hand wasn't checked before saving. The database's uniqueness rule rejected it, and the app showed only the generic message. |
| **Fix**          | It now says "Employee no. E-100 is already used by Ben Cruz."                                                                                           |

### 1.3 Other reasons the form refuses (working as designed, with clear messages)

| Message                                                                                                    | Cause                                             | What to do                                                         |
| ---------------------------------------------------------------------------------------------------------- | ------------------------------------------------- | ------------------------------------------------------------------ |
| "The Free plan allows 5 people. Upgrade…"                                                                  | Plan seat limit                                   | Upgrade, or set the company's plan in the operator console         |
| "\<email\> is already on your team."                                                                       | An active person already has that email           | Use a different email, or archive the old person first             |
| "Terminal ID 42 is already used by …" / "That card is already assigned to …"                               | Duplicate terminal ID or RFID card                | Use a free one                                                     |
| "Ask HR or an admin to add people."                                                                        | Timekeepers can't add people (they can't see pay) | Sign in as owner, admin or HR                                      |
| "Only owners and admins can add managers or admins." / "HR and timekeeper roles need the Enterprise plan." | Role rules                                        | Sign in as owner or admin; HR and timekeeper roles need Enterprise |

### 1.4 Check which code your live site runs

`origin/main` is still at commit `2e740b7` (Phases 0–5). The Enterprise work, the scaling fixes and these fixes are only on `claude/quirky-hopper-opfous`. If Vercel deploys `main`, your site doesn't have any of them. To fix it, do one of these:

- Merge that branch into `main`, with a pull request if you want one.

## 4. How to check on your deployment

1. Open `https://<your-domain>/api/health`. It should return `"status":"ok"`. A 503 means `configError` lists which settings are missing.
2. Add a person **with** an email:
   - **Success with no warning:** email works.
   - **Success with a yellow warning:** the email setup is wrong. The warning says why (see 1.1).
3. Add a person **without** an email. If this fails, read the message. It now names the cause, e.g. plan limit or a duplicate number.
4. If you still see "Something went wrong", look at Vercel → Logs for the request. The full error is logged on the server.
